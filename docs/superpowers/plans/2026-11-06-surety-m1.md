# Surety M1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tested harness core plus the M1 offline calibration study: Kev-4B and Clef-flash on WebJev decisions, with debiasing, recalibration, conformal and adaptive-conformal gates compared against threshold baselines on held-out websites.

**Architecture:** Pure-Python units (`types`, `decide`, `calib`, `gate`, `eval`, `supervise`) that talk to local model servers over HTTP (`/v1/systemone` for decision models, OpenAI chat for the supervisor). Experiments are scripts writing JSONL under `runs/`; analysis regenerates markdown tables under `results/`.

**Tech Stack:** Python 3.12, uv, pytest, httpx, pyarrow, numpy, matplotlib. Kev server (`third_party/kev`), Clef MLX (`clef_mlx.py serve`), `mlx_lm.server` for the supervisor.

**Spec:** `docs/superpowers/specs/2026-11-06-surety-design.md`

## Global Constraints

- Python `>=3.12,<3.14`; package name `surety`, dist name `surety-cua`; Apache-2.0.
- Executor never generates text; only picks among `Option.id`s. Supervisor text limited to plans/slot values.
- All backends speak the System One request shape: `{"model","state","questions":{qid:{"type","instructions","criteria"}}}`; answers at `answers[qid]["probabilities"]` keyed by option id.
- Kev rejects states > 65,536 tokens with 422; Clef truncates at 16,384. Client caps `state_text` at `max_chars` (default 40,000) before sending.
- Conformal target: autonomous error rate = `#(|C|=1 ∧ wrong)/N ≤ ε` (follows from marginal coverage ≥ 1−ε).
- Comments only where code cannot say it; one-line test names.
- `data/`, `runs/`, `third_party/` gitignored.

## Review Focus

1. Backend answer missing an option id or probabilities not summing to 1 → `SystemOneClient` fills 0 and renormalizes (Task 2 test `test_choice_renormalizes_partial_probabilities`).
2. Duplicate option ids inside one WebJev instance → `compile_instance` suffixes `_2`, `_3` and keeps `gold` mapping correct (Task 5 test `test_compile_dedupes_option_ids`).
3. Single-option instance → every policy acts, conformal set size 1, no crash (Task 4 test `test_conformal_single_option_acts`).
4. Over-long state → client truncates to `max_chars` and sets `ChoiceAnswer.truncated=True` (Task 2 test `test_choice_truncates_long_state`).
5. Supervisor returns text outside the candidate set → `choose` returns `None` so the loop escalates further instead of acting (Task 8 test `test_choose_rejects_unknown_option`).

### Task 3: Gate policies

**Files:** Create `src/surety/gate/__init__.py`, `policies.py`, `critical.py`; Test `tests/test_gate.py`, `tests/test_critical.py`

**Interfaces (Produces):**
```python
class GatePolicy(Protocol):
    name: str
    def fit(self, probs: list[dict[str,float]], gold: list[str]) -> None     # no-op for unfitted policies
    def decide(self, probs: dict[str,float]) -> GateDecision
    def update(self, probs: dict[str,float], gold: str, weight: float = 1.0) -> None   # no-op unless adaptive

class FixedThreshold(tau)            # act iff p_max>=tau; escalate candidate_set=[]
class Margin(delta)                  # act iff p1-p2>=delta
class FittedThreshold(eps)           # fit: smallest tau on a 0.01 grid with mean(p_max>=tau and wrong) <= eps
class PerChoiceThreshold(eps)        # fit per top-option id; unseen ids use the global FittedThreshold
class SplitConformal(eps)            # fit: q = quantile(1-p_gold, ceil((n+1)(1-eps))/n); C={o: 1-p_o<=q}; |C|==1 act; |C|>=2 escalate candidate_set=C sorted by p desc; |C|==0 escalate []
class AdaptiveConformal(eps, gamma=0.02, alpha_min=0.001, alpha_max=0.5)   # SplitConformal + alpha_t; update: alpha += gamma*(eps - weight*err); alpha<=alpha_min → full set
    alpha: float
class CriticalDetector:               # rules on option label (+ url): categories payment|destructive|send|account
    def classify(self, label: str, url: str = "") -> str | None
class CriticalOverride(GatePolicy):   # wraps a policy; top option critical → escalate reason "critical:<cat>"; payment → reason "stop:payment"
```
Keyword rules (case-insensitive, word-boundary): payment: `pay|purchase|buy now|place order|checkout|confirm order|subscribe|add card`; destructive: `delete|remove|discard|clear all|erase|unsubscribe`; send: `send|post|publish|reply|submit application|tweet`; account: `sign out|log out|change password|deactivate|close account`.

- [ ] **Step 1:** Tests: `test_fixed_threshold_acts_above_tau`; `test_margin_escalates_close_top_two`; `test_fitted_threshold_meets_eps_on_calibration`; `test_split_conformal_coverage_on_synthetic` (seed 0, 2,000 cal + 2,000 test items from a known generator, eps 0.1 → coverage in [0.88, 0.93]); `test_conformal_single_option_acts`; `test_conformal_set_sorted_by_prob`; `test_adaptive_alpha_moves_toward_target` (feed 50 errors → alpha decreases; 50 correct → increases); `test_adaptive_weighted_update_scales_by_weight`; `test_critical_override_stops_payment`; `test_detector_ignores_plain_navigation`.
